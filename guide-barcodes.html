You export products to change prices, then notice a barcode displayed as scientific notation. Stop before importing. First check whether the identifier changed or the spreadsheet is only displaying it differently.

Preserve exact text, not just appearance

  1. Keep an untouched export. Open a copy in a local plain-text editor and find a known product's barcode. Compare its exact characters with your trusted source. Never put private store exports in public paste sites or forums.
  2. Check the header. Shopify now documents Barcodes, supporting multiple values. It says older exports with singular Barcode are updated to Barcodes on the next export. Do not include both headers: Shopify says that fails to import.
  3. Import identifiers as text before editing. In Excel, use Data > From Text/CSV and set identifier columns to Text in the import workflow before loading them. Inspect the transformation preview against the untouched file so an automatic conversion has not already changed a value. Menus vary by Excel version.
  4. Do not rely on later formatting to repair damage. Microsoft documents that Excel can remove leading zeros and truncate numerical data beyond 15 significant digits. Formatting cannot recover characters already lost. Return to trusted source data; do not guess missing digits.
  5. Save a separate CSV, then inspect the actual text again. Compare a leading-zero identifier, a long identifier and the rows you edited. Preserve Shopify's documented barcode separators and escaping where used. A spreadsheet's number display alone is not proof.
  6. Review the rest of the product file with Vertex Product CSV Preflight if useful. It checks supported title, option-dependency and other structural rules. It cannot prove barcodes survived or verify identifiers against your store.
  7. Stop on a mismatch. Keep the damaged copy separate, rebuild from trusted data and inspect Shopify's import details. Keep a backup and test a small subset in a suitable test store when available.
Fictional example: 00012345678905 and 12345678905 are different text. A number format displaying extra zeros does not prove the saved CSV contains the original identifier. This is an illustration, not barcode validation.
Current-tool limit: The preflight supports the current plural Barcodes header: it flags a file that has both Barcode and Barcodes, which Shopify documents as a failed import, counts values against the documented maximum of 20 per product or variant, and flags empty entries between semicolons. It does not validate barcode types, check digits or your store records, so still check identifiers separately.

Topic source: An April 15, 2026 thread reported barcodes changing during a price-edit export/import. Its comments offered several explanations. This guide does not diagnose that store; it uses Microsoft's documented conversion risks and Shopify's current specification.
