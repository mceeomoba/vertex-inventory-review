A price-only update should not quietly become a weight or variant change. Review what the entire CSV tells Shopify to replace, not just the cells you edited.

Separate changes from values to preserve

  1. Export fresh product data and keep an untouched copy. Write the intended change down, such as "change these prices; keep option values and weights."
  2. Check the overwrite setting. Shopify's documented replacement behavior applies when Overwrite products with matching handles is selected. Without it, products matching existing handles are ignored during the CSV import.
  3. Review included columns. For non-required fields, an included blank cell can overwrite a stored value as blank. Omitting a non-required column can preserve its existing value. Do not use an empty cell as shorthand for "leave unchanged."
  4. Check dependencies before removing columns. Shopify says variant-related fields such as SKU and Weight value (grams) depend on Option1 name and Option1 value. Its documentation warns that excluding those option columns can create a default variant and delete existing variants. Keep the required identity fields and all data your update depends on, including the correct options. Do not blindly reduce the file to three columns.
  5. Keep option values unchanged unless changing variants is the actual job. Shopify warns that changing Option1/2/3 values deletes existing variant IDs and creates new ones, potentially breaking third-party dependencies.
  6. Use Vertex Product CSV Preflight for a second review. Update mode checks required identity fields and flags variant-related headers without Option1 name/value. Read findings alongside the original export.
  7. Keep the backup and inspect Shopify's import details. Test a small subset in a suitable test store when available. A clean report is not approval.
Fictional example: You want to change a jacket's price but preserve its Vendor. An included Vendor column containing empty cells is not the same as leaving that column out. This does not mean every other column is safe to remove: dependencies still matter.
Tool limit: The tool does not compare the file with your live store or know your intent. It cannot certify that untouched store values will remain unchanged.
