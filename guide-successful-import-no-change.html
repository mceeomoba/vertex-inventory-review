A "success" message can hide a no-op. The usual causes: you edited a read-only column, Shopify's safety check skipped stale rows, the location didn't match, or tracking is off.

You updated an inventory CSV, imported it, got the "Inventory updated successfully" email, and the store shows the same numbers as before. Before re-importing the same file, find out which silent skip you hit.

The four documented causes to check, in order

  1. You edited a column Shopify doesn't read on import. In the All states export, most quantity columns are marked "(not editable)": Incoming, Unavailable, Committed, Available and On hand (current) describe the store at export time. The only quantity column you write instructions in is On hand (new). Editing Available or On hand (current) changes nothing on import, and no error tells you so. If you exported the simpler Available format instead, you edit the numbers under each location-name column - a different file with different rules.
  2. Shopify's safety validation skipped your rows. With both On hand (current) and On hand (new) present, Shopify compares your exported snapshot against live levels. If stock changed after you exported (sales, adjustments), affected rows don't import. Shopify documents a validation-failure notice for skipped rows. Shopify's docs warn against clearing On hand (current) to bypass this except carefully in emergencies: it removes the protection against overwriting newer stock.
  3. Your rows point at a different location than the one you're checking. Each variant needs one row per location you're updating, and the Location value is case sensitive and must match the admin name exactly. If you updated rows for one location but you're viewing another in the admin, it looks like nothing changed.
  4. The variants aren't tracked. Shopify's setup documentation says you must activate inventory tracking for a product before you can view or adjust its inventory levels. If tracking is off, a CSV quantity has nowhere to land.

A clean retry

  1. Re-export fresh from Products > Inventory, choosing All states and the locations and variants you actually intend to change.
  2. In a copy, edit only On hand (new) - whole numbers, positive, negative or 0. Leave every other column alone. Do not paste over On hand (current).
  3. Verify each variant has a row for each target location, with location names copied exactly from Settings > Locations.
  4. Review before importing. The free Vertex Inventory change review compares your fresh export with your edited copy in your browser and shows the planned quantity changes. If your edits landed in a read-only column, the review shows no planned changes - the same no-op your import would produce, visible before it reaches the store. It also flags stale snapshot values and unmatched identities. It never connects to your store or imports anything.
  5. Import, then check your email: the confirmation, and any validation-failure notice Shopify documents for skipped rows. Spot-check a few variants in the admin, at the locations you edited.
  6. If rows were skipped for stale data, re-export and redo the edit against the newer snapshot instead of clearing On hand (current). Reserve the clear-and-override move for a genuine emergency, as Shopify's own caution says.
Fictional example: A merchant pulls new stock counts from a supplier file with a spreadsheet lookup and pastes the results into the Available column of an All states export. The import reports success; nothing changes, because Available is read-only on import. Moving the same numbers into On hand (new) on a fresh export, and reviewing the planned changes first, turns the invisible no-op into a visible one. Fictional illustration, not a customer result.
Tool limit: The reviewer reads Shopify All states inventory CSVs only (UTF-8, comma-separated, up to 15 MB), never Available-only files. It can't see tracking settings, your location list, or changes after your fresh export, and it never imports. A clean review is not import approval. Keep exports and review reports private; they contain inventory identifiers.
